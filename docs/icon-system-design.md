# Icon System — Design Specification (`@qball-inc/react`)

> **Scope of this document:** this is a **DESIGN-only** artifact (mirrors `docs/tool-use-indicator-design.md`,
> WP-B-4.3 → 4.4). It defines the icon system; it does **not** build it. The companion visual oracle is
> `preview/icons.html` (a token-driven, light/dark contact sheet rendering the full set with **real
> lucide@1.17.0 + simple-icons geometry**). The follow-on **BUILD WP(s)** implement this spec; the binding plan
> below supersedes the original WP-B-4b.2 brief.
>
> **Three tracks** (expanded from two during the S92 design pass, owner-directed): **UI icons** (76, codegen
> from Lucide), **AI** (an AI indicator + agent avatars — NEW), and **Brand marks** (~26, for nominative
> identification). Counts are v1 floors.

---

## 1. Purpose & Scope

A **comprehensive, two-track icon system** for `@qball-inc/react`, seeded by the personalsite-v2 P2 consumer
ask (3 page glyphs + a brand-mark registry) but scoped per the owner directive **"comprehensive, no scope
cutting."** It also retires a real internal liability: **21 hand-rolled `*Icon`/`*Glyph` functions** across
12 component files today, each independently reproducing the same Lucide geometry (the WP-B-4.4
`SVG_PROPS` hoist already started converging on a primitive).

**Three tracks:**
- **UI icons** — comprehensive, generated by build-time codegen from Lucide. v1 floor **76 icons** across 5
  categories (see §8).
- **AI** (NEW, owner-directed S92) — an **AI indicator** (the `sparkle` affordance + an animated `shimmer`
  variant) + **agent avatars** (the static Stocky mascot + 6 robot/agent heads). See §7a.
- **Brand marks** — **~26**, for **nominative identification** (pointing to a firm — e.g. "OpenAI-compatible
  endpoint", a LinkedIn link), grouped Dev/Social/AI-vendors. NOT used as the DS's own branding. See §12.

**Honest framing (Critic, carried forward):** the literal consumer ask was ~10 icons; the v1 bar (~84) is an
~8x multiplier. It is justified **not** by the consumer but by (a) retiring the 21 internal hand-rolls and
(b) the owner's deliberate adoption-credibility bet. Generation is cheap (marginal cost ≈ one manifest line);
the one irreversible cost is **naming** — every shipped name becomes a 1.0 stability contract (see §11).

## 2. Binding Decisions (summary)

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | **Sourcing = build-time codegen from `lucide-react` as a devDependency** → emit our own inline-SVG `.tsx`. **Zero runtime dependency.** Runtime re-export stays forbidden. | Shared design language + leanness without a runtime dep; honors the no-bundle rule (the rule forbids runtime re-export, not codegen). |
| D2 | **Committed-generated output** (not generate-at-build) + a deterministic `generate:icons --check` drift gate in CI. | tsup has no pre-build hook; CI runs committed source. Committed output is reviewable, DESIGN_DENY-lintable, strict-TS-checked. |
| D3 | **Single barrel + per-icon named exports + a types-only `IconName` union + an opt-in `<Icon name>` registry.** **No `./icons` subpath in v1.** | `sideEffects:false` + tsup `treeshake:true` already make per-icon named exports individually tree-shakeable; a subpath adds 3 coupled surfaces + an unverified resolution path for zero shaking gain. |
| D4 | **a11y**: `aria-hidden="true"` by default (decorative); a `title`/`aria-label` flips to `role="img"` + `<title>` and drops `aria-hidden`. | Common path zero-config; labelled path correct-by-construction. |
| D5 | **currentColor-only / zero-hex** (DESIGN_DENY passes by construction); **SSR-safe** (drop the seeds' `window`-assign). | Matches the existing idiom; the wrapper owns color. |
| D6 | **Migrate the 21 hand-rolled UI glyphs** preserving emitted DOM + CSS-class wrappers (`.ic-*`/`.tuf__glyph`) → additive MINOR. **Exclude StockyIcon** (CSS-coupled brand mascot) and **all data-viz SVG.** Migration ships **last**, behind a **DOM-equivalence gate**. | The CSS keys off wrapper classes, not SVG internals — but the MINOR claim is gated on a test (see §10/§16). |
| D7 | **Drop `inferIcon(href)` from the published surface.** | URL→brand heuristic is app policy, not a primitive. |

## 3. Sourcing & Build Pipeline

**Generator:** `packages/react/scripts/generate-icons.mjs` — a plain Node ESM script (no `tsx`/`ts-node`/`jiti`
in the tree; Node 22 present). It introduces the **first** codegen step in the repo (`scripts/` currently holds
only `license-check.sh`).

**Mechanism (empirically validated this session):** each lucide icon ships a **named ESM export**
`__iconNode: [tag, attrs][]`. Verified against the installed `lucide-react@1.17.0`:

```js
// lucide-react/dist/esm/icons/arrow-up-right.mjs   (@license lucide-react v1.17.0 - ISC)
const __iconNode = [["path", { d: "M7 7h10v10", key: "1tivn9" }],
                    ["path", { d: "M7 17 17 7",  key: "1vkiza" }]];
export { __iconNode, ArrowUpRight as default };
```

The generator imports `__iconNode` per curated name, **strips the React `key`**, and emits one `.tsx` per icon
from a template matching the `SVG_PROPS` const in `ai/ToolUseIndicator.tsx:82` byte-for-byte. (All 76 curated UI
names were extracted this way to build `preview/icons.html` — the codegen premise is proven, not assumed.)

**Alias resolution (real, found this session):** some lucide names are **alias stubs** that re-export only
`default` (no `__iconNode`) — e.g. `filter → funnel`, `circle-help → circle-question-mark`. The generator MUST
resolve aliases to canonical names. The curation manifest stores **canonical** names; the friendly alias is
recorded in the alias map (§11) and may be re-exported as a named alias.

**Output:** committed `.tsx` under `packages/react/src/icons/ui/` (generated) and `src/icons/brand/` (curated).
Each file carries a provenance header: `// AUTO-GENERATED by scripts/generate-icons.mjs from lucide-react@1.17.0 (ISC). Do not edit.`

**Determinism & pinning:**
- Pin `lucide-react` **exactly** (`1.17.0`) in **devDependencies** — distinct from the `>=0.400.0` *peer* range at `package.json:59`. (The peer range stays; it is the optional-peer posture, not the generator input.)
- `generate:icons --check` regenerates to a temp dir and diffs against committed output; non-zero on drift. Wire into `ci` so a stale commit or an un-regenerated pack bump fails loudly.
- No timestamps in output bodies (only the version in the header) so the `--check` diff is stable.

## 4. Conventions (the one idiom, normalized)

Every generated icon matches the established DS idiom exactly (already hand-rolled 21×):

- `viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `strokeLinecap="round"`, `strokeLinejoin="round"`.
- `strokeWidth` default **1.5** (exposed as a prop; the idiom uses 1.6 for a few heavier marks).
- Render size via a **`size` prop → `width`/`height`** on the fixed 24 viewBox (normalizes the one real
  inconsistency: existing call sites hardcode 16/17/19/21). **Not `1em`** (that changes the default sizing
  contract — a v2 option).
- Names are **kebab-case matching lucide ids** (`arrow-up-right`), so the `IconName` union is mechanically
  derivable and stable across pack updates.
- Brand marks share the same template + `IconProps` surface but may use `fill="currentColor"` (filled logos).

## 5. Component API — `IconProps`

```ts
interface IconProps extends Omit<SVGProps<SVGSVGElement>, "ref"> {
  size?: number;        // default 24 → width & height
  strokeWidth?: number; // default 1.5 (1.6 for heavier marks)
  className?: string;   // merged after a base "ic" class
  title?: string;       // a11y — see §9; presence flips to role="img" + <title>
  // ...rest: onClick / style / data-* / aria-* passthrough
}
```

- **Color**: `currentColor` only. Icons never read tokens; the *placement wrapper* owns color
  (`.iconbtn{color:var(--text-muted)}` → hover `var(--color-signal)`). A consumer recolors by setting `color`
  on any ancestor (or `style`), and resizes via `size`.
- **Strict-TS**: fully typed props, no string-indexed `Record` in the per-icon components (the registry handles
  `noUncheckedIndexedAccess` with an explicit guard — §6).

## 6. Export Architecture

**Single barrel (`src/index.ts`). No `./icons` subpath in v1.** Ship three shapes:

1. **Per-icon named components** (primary, documented default) — `import { TrendingUp } from "@qball-inc/react"`.
   `sideEffects:false` + `treeshake:true` make these individually shakeable; N imports ship N icons' bytes.
2. **Types-only `IconName` union** — `type IconName = "arrow-up-right" | "trending-up" | …`. Pure type, zero
   runtime cost; the contract surface for dynamic name use.
3. **Opt-in `<Icon name>` registry** — `<Icon name="trending-up" />` for dynamic/data-driven choice. Documented
   as **non-shaking** (the backing map retains the set); consumers who want shaking use the named export.

**Why no subpath (adjudicated):** the PM proposed `./icons` for the bundle-sensitive Astro consumer, but the
goal ("N imports → N icons") is **already delivered** by named-export shaking off the single barrel. A subpath
would force `tsup.entry` + `package.json#exports` + the consumer fixture (which today imports only `Button`) to
move in lockstep — a new resolution failure mode for **zero** shaking gain.

**Re-open trigger (measurement, not anticipation):** BUILD-B1 ships a **positive bundle-shaking test** (import
one icon, run the real tsup/vite build, assert a *different* icon's unique path-`d` is absent from the emitted
bundle). **Only if that test fails** on the real consumer does the `./icons` subpath earn its keep — and then it
moves all three surfaces in lockstep *with* a fixture import that exercises it.

## 9. Accessibility Contract

- **Default decorative**: `aria-hidden="true"`. Matches every current call site (adjacent text / a labelled
  control carries the meaning).
- **Labelled path**: when `title` (or an incoming `aria-label`) is supplied, emit `role="img"`, a `<title>`
  child linked via `aria-labelledby` to a generated id, and **drop `aria-hidden`** (an `aria-hidden` + `role=img`
  element is contradictory). Detect either `title` or a passed `aria-label`.
- **Guidance** (documented): decorative icon next to text → leave default; icon-only meaningful control → pass
  `title`/`aria-label`.

## 10. Migration Plan (the 21 hand-rolled glyphs)

**Approach:** swap each inline glyph definition for an import of the generated component, **preserving the exact
emitted DOM + surrounding CSS-class wrappers**. Example: `ThemeToggle`'s inline `SunIcon`/`MoonIcon` → `<Sun/>`/
`<Moon/>` still wrapped in `<span class="ic-sun">`/`<span class="ic-moon">` (the shipped CSS swap keys off the
wrapper classes, not SVG internals). Same for `.tuf__glyph` (ToolUseIndicator). Public barrel exports + emitted
class-DOM unchanged → **additive MINOR**.

**Sequencing:** ship the generated set + named exports FIRST (purely additive); migrate call-sites incrementally
**last**, lowest-coupling first (Modal/ThemeToggle early; the mascot-adjacent last).

**Carve-outs:** `StockyIcon` (32-viewBox multi-element brand mascot; token CSS animates `.stocky-*` classes and
hardcodes its fill — legal, outside the `packages/*/src` DESIGN_DENY scope) is **excluded**. Data-viz SVG
**excluded** (§8).

**Gate (binding — see §16 Risk-1):** migration does NOT begin until a **DOM-equivalence gate** is green:
1. `grep -rE "toMatchSnapshot|querySelector\(['\"](path|svg)" packages/react/src` over the 21 sites to find any
   test asserting SVG internals.
2. Per migrated component, a test asserting the post-migration emitted SVG matches the pre-migration one
   byte-for-byte (path data + element order + wrapper class).
3. If a glyph's hand-rolled geometry differs from lucide-canonical, the BUILD WP DECIDES per-icon: keep the
   hand-rolled geometry (don't migrate that one) or accept + document the visual change.

## 11. Naming Convention & Stability Contract

- **Convention**: kebab-case = lucide canonical id. Category is organizational (docs/manifest), **not** a name
  prefix, unless two icons would collide.
- **Alias map** (canonical → friendly aliases; first concrete entries found this session):
  `funnel` ← `filter`; `circle-question-mark` ← `circle-help`. Aliases may be re-exported as named aliases so a
  consumer's intuitive name still resolves.
- **Stability contract (1.0)**: every shipped icon name is a **semver-MAJOR-to-rename** commitment. The curated
  list + alias map are **locked at owner sign-off** and frozen at 1.0.0. Adding icons later is MINOR; renaming or
  removing is MAJOR. This is the single highest-leverage control (naming is the one irreversible cost).

## 12. Licensing & Trademark Posture

- **UI track**: Lucide is **ISC** (verified in `lucide-react@1.17.0` `package.json` + each icon's `@license`
  header — **not "MIT"** as the brief claimed, SD1 D-14). ISC is permissive and Apache-2.0-compatible. The
  generated `.tsx` carries a provenance header citing the exact pack version + SPDX.
- **Pack-license assertion is a NET-NEW BUILD deliverable**: the existing CI `scripts/license-check.sh` is a
  **font-binary leak scanner**, not an SPDX/package check — it neither trips on nor validates a pack devDep. The
  BUILD WP adds an explicit version-pin + SPDX-record step.
- **AI track**: `ai-sparkle` + `bot`/`bot-message-square`/`cpu` are lucide (ISC, codegen); `agent-stocky` reuses
  the DS's own mascot geometry; `agent-orb`/`agent-droid`/`agent-hex` are **original DS art** (no third-party
  source). No external license encumbrance beyond Lucide ISC.
- **Brand track — NOMINATIVE use.** These marks **identify / point to** a firm (an OpenAI-compatible endpoint, a
  LinkedIn link) — they are **not** the DS's own branding. All are the **trademarks of their respective owners**,
  reproduced for identification only, no affiliation/endorsement; a disclaimer ships (gallery + a `MARKS.md`).
  **Per-mark sourcing (S92, empirical):**
  - **simple-icons (CC0)** — most marks (figma, notion, vercel, npm, reddit, google, chromestore, + AI vendors
    anthropic, claude, gemini, deepseek, moonshot, mistral, perplexity, huggingface, ollama, qwen, meta). Add
    `simple-icons` as a **devDep** at BUILD (parallels the lucide codegen pattern; CC0 → no runtime/license issue).
  - **Owner-provided assets** — `openai` + `glm` (the owner supplied SVGs; not in CC0 sets — their owners had them
    withheld). Committed to `src/icons/brand/` at BUILD; the `#000000` fill normalized to `currentColor`.
  - **In-repo asset** — `linkedin` (the generic stylized stroke glyph from the consumer's own `sections.jsx`;
    Lucide removed brand icons, so it is NOT in lucide@1.17.0 — carry the owner's asset). Stroke-style (the rest
    are filled) — a minor visual inconsistency the owner accepted; revisit if a filled mark is wanted.
  - **Stand-in** — `vscode` shown as **VSCodium** in the preview (the real VS Code mark is trademark-withheld from
    CC0); BUILD swaps in the official asset or keeps the stand-in.
  - **Key finding:** several major marks (openai, the real vscode, linkedin, glm, grok/xAI) are **withheld from CC0
    sets at their owners' request** — sourcing them needs owner-provided/official assets, not a CC0 pull. This is
    the trademark posture made concrete.

## 13. Testing Strategy (T1–T4, real behavior)

- **DOM/a11y (real render)**: render a per-icon export + `<Icon name>`; assert `<svg>` with `viewBox="0 0 24 24"`,
  `stroke="currentColor"` (or `fill` for filled marks), `aria-hidden` default, and that `title`/`aria-label`
  flips to `role="img"` + label. Assert emitted DOM, not snapshot blobs.
- **Contract/determinism**: a SOURCE test reading the curation **manifest** asserts the generated registry
  exports **exactly** that set (no missing/extra); paired with `generate:icons --check` in CI.
- **Tree-shakeability (observable)**: the consumer fixture imports ONE icon, real tsup/vite build, assert a
  *different* icon's unique path-`d` is **absent** from the emitted bundle. (Also the §6 subpath re-open trigger.)
- **Migration equivalence**: per §10 gate.
- **DESIGN_DENY-scans-tests trap**: `eslint.config.mjs` deny-rule scopes `packages/*/src/**` **including
  `*.test.tsx`** — tests use `currentColor`/named colors only, broad-substring assertions, never hex regex
  literals (per the DESIGN_DENY self-assertion memory).
