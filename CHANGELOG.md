# Changelog

This is the curated, cross-package overview. Detailed per-version entries are generated by
Changesets into each package's own changelog (`packages/tokens/CHANGELOG.md`,
`packages/react/CHANGELOG.md`, `packages/elements/CHANGELOG.md`) at release time; this file
is the human summary that ties them together.

The versioning contract (token / type-stack / radius-scale changes = MAJOR; additive
component / variant = MINOR) is defined in `CAVEATS.md` and enforced via Changesets
in the release pipeline.

## Release C — @qball-inc/elements 0.5.0, @qball-inc/tokens 1.3.0, @qball-inc/react 1.0.8 — 2026-10-20

**`@qball-inc/elements` 0.5.0** adds `GraphExplorer` to `./graph`: the canvas, the facet
filter chips and the entity details panel in one dark-stage frame. Clicking entities builds
a path; the panel narrates each hop with the claims behind it, through your own `detail`
callback. The explorer reports `pathchange`, `panel` and `error` events for URL sync and
launcher yield, and never fetches or writes history. `FacetFilterBar` and `EntityPanel`
ship as their own renderers too, and answer-turn toggles now carry `aria-controls`. `three`
stays an optional peer: a site that mounts the explorer without it still builds, and the
explorer shows its error figure. The consumer hand-back gives a one-line CI check for
that. This is renderer-only: backend integration is a later, gated step. Guides:
[docs/graph-explorer.md](./docs/graph-explorer.md),
[docs/entity-panel.md](./docs/entity-panel.md), and the Release C section of
[docs/consumer-handback-elements.md](./docs/consumer-handback-elements.md).

**`@qball-inc/tokens` 1.3.0** (minor) adds `--signal-strong` (the pressed facet chip label,
AA in every theme), the panel and chip styles, and full-width connection rows.
**`@qball-inc/react` 1.0.8** has no code changes; it depends on `@qball-inc/tokens` 1.3.0.

## Interim release — @qball-inc/elements 0.4.0, @qball-inc/tokens 1.2.0, @qball-inc/react 1.0.7 — 2026-10-18

**`@qball-inc/elements` 0.4.0** ships the 3D knowledge-graph canvas in `./graph`
(`GraphCanvas.mount`), with `three` loaded lazily as an optional peer, a seeded layout that
settles in a Web Worker, and `computeLayout` for precomputing that layout on a server
([docs/graph-canvas.md](./docs/graph-canvas.md)). Chat links can open in a new tab
(`openLinksInNewTab`, with your own `newTabLabel`), and site links under an answer now
look like the sources list. Patches 0.3.1 to 0.3.3 added restoring a visitor's earlier
vote, an overlay that follows the on-screen keyboard, and the status-text and site-links
slots.

**`@qball-inc/tokens` 1.2.0** (minor) adds the canvas label rules and the `--stage-hub`
token, and removes the old site-links classes (use with elements 0.4.0 or later).
**`@qball-inc/react` 1.0.7** has no code changes; it depends on `@qball-inc/tokens` 1.2.0.

## Release B — @qball-inc/elements 0.3.0, @qball-inc/tokens 1.1.2, @qball-inc/react 1.0.4 — 2026-10-11

**`@qball-inc/elements` 0.3.0** completes the `./chat` entry with answer turns.
`mountTranscript` renders a conversation into the ask overlay (or any element); each bot
turn is an `AnswerTurn` whose streamed draft never reaches the page until it is finalized.
It renders every verdict (grounded, withheld, refused), error turns and limit notices, and
adds a disabled-composer switch for usage limits and `safeInternalUrl`, the policy for an
answer's explorer link and notice actions. The input model now allows a grounded answer
with no evidence (`0 claims · 0 episodes`) and an optional snapshot date. This is
renderer-only: backend integration is a later, gated step. Guides:
[docs/qubae-answers.md](./docs/qubae-answers.md), and the Release B section of
[docs/consumer-handback-elements.md](./docs/consumer-handback-elements.md).

**`@qball-inc/tokens` 1.1.2** (patch) adds the answer-turn styles and makes the trust and
chat components meet WCAG AA colour contrast in both themes, by restyling the components;
no token values change.

**`@qball-inc/react` 1.0.4** has no code changes; it depends on `@qball-inc/tokens` 1.1.2.

## Interim release — @qball-inc/elements 0.2.0, @qball-inc/tokens 1.1.1, @qball-inc/react 1.0.3 — 2026-10-10

**`@qball-inc/elements` 0.2.0** gives the claim card one fixed two-row layout at every
width, with status labels in their own strip above the sentence, and ships the first part
of `./chat`: `mount()`, the ask launcher (`Q` hotkey) and the modal ask overlay
([docs/chat-launcher.md](./docs/chat-launcher.md)).

**`@qball-inc/tokens` 1.1.1** (patch) carries the claim-card layout styles and fixes the
mascot ink on the launcher over the dark graph stage. **`@qball-inc/react` 1.0.3** has no
code changes; it depends on `@qball-inc/tokens` 1.1.1.

## Release A — @qball-inc/elements 0.1.0, @qball-inc/tokens 1.1.0, @qball-inc/react 1.0.2 — 2026-10-10

First release of **`@qball-inc/elements`**, framework-free TypeScript + DOM components that
paint the tokens CSS (no React needed). `0.1.0` ships the trust components
(`@qball-inc/elements/trust`: claim card, source row and reading list, provenance footer,
verdict stamp, answer feedback) and the input model (`@qball-inc/elements`: types,
validator, confidence and superseded semantics, locked-string formatters, AnswerTurn). The
`./chat` and `./graph` entries are placeholders until later releases. The package stays on
`0.x` until its data contract is final. Consumer guide:
[docs/consumer-handback-elements.md](./docs/consumer-handback-elements.md).

**`@qball-inc/tokens` 1.1.0** (minor, additive only) adds the styles these components
paint: the trust, chat and entity-panel classes in `components.css`, the new opt-in
`graph.css` (graph and explorer chrome on a pinned dark stage), and the theme-independent
`--stage-*`, `--color-scrim-light` and `--text-scale` tokens. Import order:
`colors-and-type.css` → `components.css` → `graph.css`.

**`@qball-inc/react` 1.0.2** has no code changes; it depends on `@qball-inc/tokens` 1.1.0.

## @qball-inc/tokens 0.1.0 — 2026-06-18

First public release of the token layer, as early-access `0.x`. Ships the token surface
extracted verbatim from the design system: framework-agnostic CSS custom properties
(`theme.css`, `colors_and_type.css`), the shipped component classes (`components.css`),
and the DTCG / Style-Dictionary JSON mirror (`tokens.json`). Zero build step; the public
default display face is Fira Code (Berkeley Mono is restored in private builds per README).

While on `0.x` the token surface may still gain or adjust tokens on the road to `1.0.0`.
The strict semver contract (any token-value / type-stack / radius / spacing change = MAJOR)
defined in `CAVEATS.md` takes effect at `1.0.0`, when `@qball-inc/tokens` and
`@qball-inc/react` are published together.

`@qball-inc/react` is not yet published — it is still gaining component families ahead of v1.
